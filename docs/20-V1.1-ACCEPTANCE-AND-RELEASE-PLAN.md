## Scope and ownership

Validate the existing post-v1 library and both consumers as a bounded 1.1 release:
Compact/Touch density, Simplified layout/customization, feature availability,
Crystal and Office 2024 Flat, shared glass/backdrop integration, QAT command
projections/icon choices, gallery/combo/menu improvements, layout transitions,
designer authoring and the completed Writer host integration.

The source revision above is the starting inventory, not a permanently frozen
release candidate. Record the actual source revision and local changes for each
execution. New fixes require an impact-based verification decision; new features
require a scope decision rather than being added to acceptance work implicitly.

User clarification from the **Prepare Writer host for 1.1** chat is carried into
this campaign: physical/native touch and OS IME testing are not required. Exercise
Touch density through mouse, keyboard and automated controls. Existing synthetic
composition/fallback regressions remain useful; they do not imply an IME claim.

Keep these outside 1.1 completion requirements: grouped Writer font UI, automatic
device detection, new document features, editable multipage layout, remaining MDI
milestones, full Windows contrast-theme support, production RTL certification and
physical-printer certification. Retain existing regression coverage and document
known limitations; exclusion does not excuse a regression in supported behavior.

This file owns campaign status, gate decisions and release readiness. Existing
subsystem plans retain their detailed acceptance and implementation evidence.
Record an observation at its owning subsystem and link it here; do not duplicate
confirmation prose across the design index, history and README.

### Intentional behavior and customization notes for A9

- **Office 2007 default File presentation:** the shared style now follows
  `RibbonKit.ApplicationButtonShape.Default`, selecting Orb for Office2007 and
  Tab elsewhere. A consumer relying on the former Office2007 File-tab default can
  retain it with explicit `ApplicationButtonShape="Tab"`. Local values retain WPF
  precedence. This previously approved behavior must be mentioned in 1.1 notes;
  unchanged enum/API/registration metadata does not mean unchanged effective style.
- **Keyboard entry:** Ribbon now overrides Focusable/IsTabStop to false so the
  container is skipped while its commands remain keyboard destinations. This is
  the documented navigation correction, not a removed command or KeyTip API.
  Consumers explicitly focusing the container should review their focus routing.
- **More specific theme tokens:** ScreenTip background now uses
  `RibbonKit.Brushes.ScreenTip.Surface`; RibbonTextBox uses
  `RibbonKit.Brushes.Input.SurfaceBackground` / `.Input.Border`; Options action
  buttons use `.Dialog.ActionBackground` / `.Dialog.ActionBorder`. Legacy keys
  remain, but overrides of the previously shared brushes may no longer repaint
  these individual surfaces. Include an override-mapping note rather than claiming
  complete visual equivalence for custom themes. Menu minimum width now follows
  `RibbonKit.Metrics.MenuItemMinWidth` (200 in the Office dictionaries reviewed,
  versus the old 160-DIP style literal); narrow-window checks remain in A5.
- **Customization template refactoring:** apparent removed TreeViewItem selection/
  expansion setters are inherited from `RibbonKit.Customize.TreeContainerStyle`;
  message actions use a named shared style and gallery side buttons fill their
  allocated rows. These are shared presentation changes, not confirmed missing
  bindings. Preserve the associated runtime/visual checks rather than treating the
  same-file setter comparison as a product failure.
- **New optional presentations:** Compact/Classic remain the runtime defaults.
  Hosts own density/layout selection and persistence; the new Writer preferences
  do not alter document data or rewrite saved ribbon structures. Downgrading a
  profile that selects a new enum value into an old app is not forward-compatibility
  coverage and is not promised by this review.

Static evidence is under `TestResults/v1.1-compatibility/`: `api-enum-inventory.json`,
`default-metadata-inventory.json`, `template-token-inventory.json`,

`persistence-inventory.json`. The inventories narrow review candidates and are not
